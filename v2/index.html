PQ attestation aggregation: finality time and aggregator work

Every validator votes at once; votes are proven into leaf proofs, merged up a tree, and folded into one block proof by several redundant stake-sampled folders, so the proposer is not a single point of failure: it only includes the first valid block proof it receives. Finality takes two such rounds. Aggregators are sampled by stake from all attesters. Tree shape and per-level redundancy are optimised for the inputs you set (or fixed manually). Draft model; see assumptions at the bottom.

Model and assumptions

  • Work unit. 1 AWU = proving one 100-signature leaf on one thread (1.005 s, Xeon Gold 6548N). Leaf time is linear in signatures (only 100 is measured). Merge time is a + b·k, fit to the 2→1 and 4→1 runs; thread scaling is interpolated between 1, 4, 8, 16 threads.
  • Rounds. Each round: signatures reach leaf aggregators, leaves are proven, proofs move up L merge levels, roots reach r stake-sampled folders who each fold them into the block proof (fan-in ≤ MAX_RECURSIONS) and send it to the proposer, who includes the first valid one; the block proof is then gossiped. The proposer is no longer a single point of failure for the fold; it should not be bound to one proposer, so the next proposer can include the same proof. Levels do not overlap. Finality = rounds × round time.
  • Sampling and stragglers. Each job is given to r validators drawn by stake. A level closes when the deadline share of its jobs (default 95%) has a finished copy; jobs whose copies all sit on slower nodes are dropped and their votes counted as lost. Nodes holding several jobs at once run them back to back.
  • Redundancy. A copy fails with probability q + (1−q)·offline. Per-level r is chosen by dynamic programming over a split of the loss budget β, so that each level's binomial tail ≤ ε/(L+1), minimising work. "Loss bound" is the union bound over levels with the chosen budget split (for manual redundancy, an even split).
  • Cost. Per node: busy thread-seconds per round × rounds per year, priced either as electricity (watts per busy thread × $/kWh) or as rented cloud thread-hours. Nodes per tier = stake share × N ÷ validators per node. $/ETH/yr divides a node's cost by the stake it runs; with stake-proportional sampling it differs across tiers only through hardware efficiency.
  • Bandwidth. Each tier's upload and download are multiplied by the bandwidth share (default 20%) to leave room for payloads, blobs, votes and gossip overhead. This is a flat share; it does not model when bulk-data bursts happen relative to aggregation.
  • Signatures (v2). In gossip mode every subscriber of a subnet receives and relays all of its signatures. Per-node load = backbone subnets × signatures per subnet × (signature + overhead) × duplicates. The subnet drains at the node-weighted mean of min(upload, download) × bandwidth share across all nodes (home nodes relay as much as pro nodes), plus hops × ½ RTT. This replaces v1's fixed 1,000 signatures/s per subnet. It assumes perfect load balancing across relays, so it is optimistic for home-heavy subnets. Calibration: Sukun's simulations, P2P call #10.
  • seacast (v2). Optional proof broadcast: hops × ½ RTT + overhead × size ÷ stake-weighted relay upload + one verification. From Csaba's seacast results on P2P call #10; not yet specified or deployed.
  • Verification. Each proof check costs the verification time (default 3.5 ms, leanVM benchmarks): k checks before every merge, one per root at each folder, one at the proposer, and one per gossip hop for relays.
  • Not modelled. Overlap between levels, gossip duplicates beyond D, CPU contention with attesting, signature verification by non-aggregators, picking up missed votes in the next round.
  • Sources. leanVM benchmarks; EIP-8292 (proof ~230 KiB, 1 s propagation target); EIP-7870 (hardware tiers); Anton Nashatyrev's gossip simulations; PQ interop call #43 (Shadow: p95 block propagation ~2 s at 50 Mbps).
